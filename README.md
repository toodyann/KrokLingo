# KrokLingo

[![Deploy](https://github.com/toodyann/KrokLingo/actions/workflows/deploy.yml/badge.svg)](https://github.com/toodyann/KrokLingo/actions/workflows/deploy.yml)

Тренажер для підготовки до іспиту **«Крок 1. Стоматологія»**. У ньому є симуляція іспиту з таймером, тренування за темами й словник невідомих слів із перекладом по кліку. Питання доступні англійською й українською, загалом близько 5500.

**Сайт:** https://toodyann.github.io/KrokLingo/ (встановлюється як застосунок, працює офлайн)

- **Фронтенд** — React на GitHub Pages.
- **Банк питань** — на сервері (Fastify на Render, PostgreSQL у Supabase); на пристрої зберігається його копія.
- **Без входу** історія, словник і налаштування зберігаються в браузері.
- **З входом через Google** вони синхронізуються між пристроями.

## Можливості

- **Головна.** Дашборд за 7, 30 чи 90 днів або за весь час:
  - чотири картки: серія днів, відповіді, точність, нові слова (зі зміною відносно попереднього періоду);
  - блок прогресу й швидкі дії: продовжити тест, симуляція іспиту, тренування за темами, повторити слова, робота над помилками;
  - графіки правильних відповідей, результатів спроб відносно порогу, росту словника й точності за темами.
- **Симуляція іспиту.** За замовчуванням 50 завдань, 100 хвилин і поріг 40%; усе це змінюється в налаштуваннях. Коли час вийде, іспит завершиться автоматично.
- **Тренування.** Без обмеження часу. Можна вибрати збірники й теми, кількість питань або повторювати лише помилки. Тест за однією темою — 20 питань в один клік.
- **Мова питань.** Перемикач English / Українська на сторінці «Тести» діє для іспиту, тренувань і помилок. Історія й результати показують обидві мови.
- **Переклад по кліку.** Кожне слово англійського питання, тексту для читання чи варіанта можна натиснути. Переклад відкривається поруч зі словом на комп'ютері або в аркуші знизу на телефоні (закривається свайпом). Слова, які вже є у словнику, підсвічені маркером у всіх текстах.
- **Словник.** Натиснуті слова зберігаються автоматично. Їх можна редагувати, позначати вивченими, повторювати картками й експортувати в `.txt` чи `.docx`. Видалення можна скасувати.
- **Під час тесту.** Видно таймер, номер питання, правильні й неправильні відповіді та поточний відсоток. Тест можна покинути й продовжити пізніше.
- **Історія і звіти.** Спроби згруповані за днями. Звіт кожної спроби містить бали, час, вердикт «склав / не склав», розбір кожного питання й нові слова сесії.
- **Профіль.** Вхід через Google вмикає синхронізацію. На комп'ютері кнопка облікового запису внизу сайдбару, на телефоні вкладка «Профіль» з картинкою Google.
- **Імпорт збірників** у JSON і **резервна копія** всіх даних.

## Банк питань

5461 питання: 3193 англійською (117 оригінальних і понад 3000 з буклетів 2006–2024) і 2268 українською (буклети 2010–2026).

| Збірник                              | Що всередині                                                                                                               |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Базові медичні дисципліни (88)       | оригінальні ситуаційні задачі з поясненнями                                                                                |
| Професійна англійська (29)           | оригінальні: термінологія, граматика, читання (4 тексти)                                                                   |
| Буклет 2006 … Буклет 2022            | офіційні англомовні буклети ЦТ «Крок 1. Стоматологія» (2006, 2019, 2021, 2022 і доповнення інших років — з посібника БДМУ) |
| Англійська 2022, 2023, 2024 (97–117) | іспит з англійської мови професійного спрямування: тексти для читання і клінічні питання                                   |
| Буклет 2010 … 2026 (укр.)            | україномовні буклети ЦТ: ЄМУ (2010–2024) і medical-club (2020–2026)                                                        |

- Питання, що повторюються в різні роки, лишаються лише в найновішому буклеті.
- Теми для буклетів визначено автоматично за ключовими словами: за перевіркою на розмічених питаннях точність близько 86–88%, тож де-не-де тема може бути неточною.
- Джерела й скрипти збірки описано в [`apps/api/scripts/booklets`](apps/api/scripts/booklets/README.md).

Банк зберігається у файлах `apps/api/bank/*.json`, по одному на збірник. Під час старту API копіює їх у таблиці `bank_*`. Застосунок отримує банк через `GET /api/bank` і тримає копію в IndexedDB, тому повторні запуски миттєві й працюють офлайн. Зміни підтягуються у фоні.

Теми відповідають дисциплінам Кроку 1 ([`apps/web/src/data/topics.ts`](apps/web/src/data/topics.ts)):

- медична біологія;
- анатомія (загальна та голови, шиї й зубів);
- гістологія та цитологія;
- ембріологія;
- фізіологія;
- біохімія;
- мікробіологія та вірусологія;
- імунологія;
- патологічна фізіологія;
- патологічна анатомія;
- фармакологія;
- термінологія та граматика;
- читання.

### Вбудований словник

Для англійських слів є офлайн-переклад: близько 1400 базових форм, а також фрази, латина й абревіатури. Лематизатор зводить словоформи до словникових: `teeth` → `tooth`, `caused` → `cause`, `bacteria` → `bacterium`.

Слова, яких немає у вбудованому словнику, перекладаються онлайн через MyMemory. Онлайн-переклад можна вимкнути в налаштуваннях. Знайдений переклад зберігається у словнику, тож повторно сервіс не запитується.

## Формат імпорту (JSON)

```json
{
  "collection": "Буклет 2024",
  "questions": [
    {
      "topic": "anatomy",
      "text": "Which nerve provides motor innervation to the muscles of mastication?",
      "options": ["Mandibular nerve", "Maxillary nerve", "Facial nerve", "Hypoglossal nerve", "Vagus nerve"],
      "correct": "A",
      "explanation": "Optional explanation."
    },
    {
      "topic": "reading",
      "passageTitle": "Dental caries",
      "passage": "Reading text shown above the question…",
      "text": "According to the text, …",
      "options": ["…", "…", "…", "…", "…"],
      "correct": 2
    }
  ]
}
```

- `correct` можна задати трьома способами:
  - літерою: `"A"`–`"E"`;
  - номером-рядком: `"1"`–`"5"`;
  - індексом від 0: `0`–`4`.
- `topic` — один із вбудованих ідентифікаторів або будь-яка власна назва. Вбудовані: `biology`, `anatomy`, `anatomy-head`, `histology`, `embryology`, `physiology`, `biochemistry`, `microbiology`, `immunology`, `pathophysiology`, `pathology`, `pharmacology`, `terminology`, `reading`.
- Питання з однаковим текстом `passage` групуються під одним текстом для читання.
- Імпортовані питання вважаються англійськими.

Шаблон можна завантажити в розділі **Налаштування → Імпорт питань**.

## Дизайн

Компоненти побудовано на [shadcn/ui](https://ui.shadcn.com/) (Radix + Tailwind CSS v4).

- **Тема.** Тема одна, темна:
  - фон `#000000`, сайдбар `#0A0A0A`, картки `#121212`;
  - білі основні кнопки з чорним текстом;
  - шість яскравих акцентів для карток статистики, дій і графіків: лайм, фіолетовий, блакитний, кораловий, жовтий, рожевий.

  Токени задано в `src/styles/tokens.css`. Змінні shadcn (`--primary`, `--card`, `--border`…) прив'язані до них у `src/index.css`, тож усі компоненти мають ту саму палітру.

- **Шрифти й маскот.** Заголовки й великі цифри набрано шрифтом Unbounded, текст — Geist; обидва шрифти локальні, з кирилицею. Маскот, усміхнений зуб, з'являється в привітанні, блоці прогресу, порожніх станах і на екрані завантаження.
- **Сітка.** Контент займає ширину поруч із сайдбаром, до 1560 px:
  - на «Головній» — 12 колонок;
  - на налаштуваннях тестів, результатах та історії — основна колонка з закріпленою бічною панеллю;
  - у словнику — таблиця на всю ширину.

  Текст питання обмежено зручною шириною (~68 символів).

- **Адаптивність.**
  - Від 768 px — сайдбар-рейка з іконками, яка розкривається поверх контенту при наведенні; внизу кнопка облікового запису з меню.
  - На телефоні — таб-бар знизу з вкладкою «Профіль» і аркуші замість поповерів.
  - Горизонтального скролу немає на жодній ширині.
- **Рух і жести.** Аркуші тягнуться пальцем і закриваються з урахуванням швидкості жесту. Пружинна анімація власна.
- **Доступність.**
  - Контраст тексту не нижчий за 4.5:1 (WCAG AA).
  - Цілі натискання 36–44 px (44 px на сенсорних екранах).
  - Видимий фокус і підказки до кнопок-іконок.
  - Враховано `prefers-reduced-motion`, `prefers-reduced-transparency` і `prefers-contrast`.
- **Скасування замість діалогів.** Оборотні дії, як-от видалення слів, можна відкотити кнопкою «Скасувати». Підтвердження з'являється лише тоді, коли дані втратяться: незавершений тест, скидання даних.

## Застосунок (PWA)

KrokLingo встановлюється як застосунок: кнопка «Встановити» в **Налаштуваннях** (Chrome, Edge, Android), на iPhone — «Поділитися → На початковий екран».

- **Кешування.** Service worker (`vite-plugin-pwa`, Workbox) кешує зібраний застосунок, а банк питань лежить в IndexedDB, тож після першого запуску все працює без інтернету. Картинка профілю Google має окремий кеш (`avatars`, оновлюється у фоні). Запити до API й Supabase завжди йдуть у мережу.
- **Оновлення.** Нова версія сама не перезавантажує сторінку, тож тест не перерветься: з'являється «Доступна нова версія → Оновити». Оновлення перевіряються щогодини.
- **Іконки.** `public/pwa-*.png`, `maskable-icon-512x512.png` (зуб у безпечній зоні) і `apple-touch-icon.png`. Ярлики на іконці: «Тести» і «Словник».

## Розробка

Монорепозиторій на npm workspaces. Потрібен Node.js 22.12+ (версія закріплена в `.nvmrc`).

```bash
nvm use
npm install
npm run dev
```

Фронтенд бере банк питань з API. Його адресу задає `VITE_API_URL` в `apps/web/.env.local` (за зразком `apps/web/.env.example`). Можна вказати продакшн-API або локальний (`npm run dev:api`, порт 8787).

| Команда                           | Що робить                                                           |
| --------------------------------- | ------------------------------------------------------------------- |
| `npm run dev`                     | Фронтенд з гарячим перезавантаженням (http://localhost:5173)        |
| `npm run dev:api`                 | API з перезапуском при змінах (потрібен `apps/api/.env`)            |
| `npm run build`                   | Перевірка типів і продакшн-збірка фронтенду в `apps/web/dist/`      |
| `npm run lint` / `lint:fix`       | Перевірка коду Oxlint                                               |
| `npm run format` / `format:check` | Форматування Prettier / перевірка без змін (з кешем)                |
| `npm run typecheck`               | Перевірка типів у всіх пакетах                                      |
| `npm test`                        | Тести всіх пакетів (API — на PGlite у пам'яті, без Docker)          |
| `npm run test:coverage`           | Те саме зі звітом покриття (`coverage/index.html` у кожному пакеті) |

У VS Code рекомендовані розширення Oxlint, Prettier і EditorConfig (`.vscode/extensions.json`). Коміт з масовим форматуванням пропускається в `git blame`:

```bash
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

### Тести

Vitest працює в кожному пакеті:

| Що                                                         | Що перевіряють                                                                                                                                                                       |

## Обліковий запис і бекенд

Без налаштування синхронізації дані живуть у браузері. Коли змінні для синхронізації задано, у **Налаштуваннях** з'являється «Увійти через Google»:

- Після входу історія, словник, налаштування, незавершений тест і імпортовані збірники зберігаються в обліковому записі.
- Під час першого входу дані, зібрані в браузері до того, переносяться в обліковий запис.
- Далі кожна зміна відправляється на сервер. Без мережі зміни чекають і відправляються, щойно з'явиться зв'язок.
- Після виходу дані залишаються в обліковому записі, а з браузера прибираються.

Банк питань спільний для всіх і доступний без входу.

- `GET /api/bank` віддає його одним стиснутим документом (brotli/gzip) з ETag. Якщо банк не змінився, відповідь — `304`.
- Під час старту API порівнює хеш файлів `apps/api/bank/*.json` з базою. Якщо файли змінилися, він перезаписує таблиці `bank_collections`, `bank_passages` і `bank_questions`.
- Щоб додати питання, достатньо змінити JSON-файл і запушити в `main`.

**Як це влаштовано:**

- **Вхід:** Supabase Auth через Google.
- **API:** Fastify перевіряє токен Supabase (через JWKS проєкту) і зберігає дані користувача в PostgreSQL Supabase через Drizzle.
- **Захист:** на всіх таблицях увімкнено Row Level Security без політик, тож доступ до даних можливий лише через API.

### Налаштування (один раз)

1. **Проєкт Supabase.** Створіть проєкт на [supabase.com](https://supabase.com). Знадобляться:
   - **Project URL** і **publishable (anon) key** — з _Project Settings → API_;
   - рядок підключення до бази — з _Connect → Connection string_ (pooler, порт 6543).
2. **Вхід через Google.**
   - У [Google Cloud Console](https://console.cloud.google.com/apis/credentials) створіть OAuth Client ID (_Web application_). Як _Authorized redirect URI_ вкажіть `https://<project-ref>.supabase.co/auth/v1/callback`.
   - У Supabase увімкніть _Authentication → Sign In / Providers → Google_ і вставте Client ID та Secret.
   - У _Authentication → URL Configuration_ додайте до _Redirect URLs_ `https://toodyann.github.io/KrokLingo/` і `http://localhost:5173/`.
3. **База даних.** Створіть `apps/api/.env` за зразком `apps/api/.env.example` і застосуйте міграції:
   ```bash
   npm run db:migrate -w @kroklingo/api
   ```
4. **API.** Локальний запуск: `npm run dev:api` (порт 8787).

   **Продакшн на Render** (безкоштовний план) уже описано в [`render.yaml`](render.yaml):
   - _Render → New → Blueprint_ → виберіть цей репозиторій.
   - Заповніть `DATABASE_URL` і `SUPABASE_URL`, решта змінних уже задана.
   - Міграції застосовуються під час старту (`MIGRATE_ON_START=true`), банк питань оновлюється теж під час старту (`SEED_BANK_ON_START`, увімкнено за замовчуванням).
   - Адреса сервісу (`https://kroklingo-api.onrender.com` або схожа) — це і є `VITE_API_URL`.
   - Безкоштовний сервіс засинає без запитів, тож перший запит після паузи триває 30–60 с. Поки сервер прокидається, застосунок показує екран завантаження (лише під час першого запуску; далі банк уже є на пристрої).

   **Інший хостинг з контейнерами** (Fly.io, Railway, Cloud Run): образ збирається з кореня репозиторію командою `docker build -f apps/api/Dockerfile -t kroklingo-api .`. Змінні середовища ті самі.

   Перевірка після деплою:
   - `GET /health` відповідає `{"ok":true}`;
   - `GET /ready` додатково перевіряє з'єднання з базою;
   - `CORS_ORIGINS` має містити `https://toodyann.github.io` (і `http://localhost:5173` для розробки).

5. **Фронтенд.**
   - Для розробки: `apps/web/.env.local` за зразком `apps/web/.env.example`.
   - Для GitHub Pages: змінні репозиторію `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_API_URL` (_Settings → Secrets and variables → Actions → Variables_). Наступний деплой увімкне вхід на сайті.

## CI і деплой

```
pull request / пуш у гілку ──► CI
пуш у main ──► CI ──► збірка ──► GitHub Pages
           └─► Render чекає на успішні перевірки коміту ──► деплой API
```

**CI** (`.github/workflows/ci.yml`) складається з двох паралельних задач:

- **Format, lint, types, build:** Prettier, Oxlint, `tsc` у всіх пакетах і збірка фронтенду.
- **Tests:** тести всіх пакетів з покриттям. Таблиця покриття з'являється в підсумку запуску, HTML-звіти — в артефакті `coverage`.

**Деплой фронтенду** (`.github/workflows/deploy.yml`) спершу запускає той самий CI. Збірка й публікація на GitHub Pages відбуваються лише тоді, коли CI пройшов. Щоб прямі посилання на розділи працювали на Pages, збірка копіює `index.html` у `404.html`.

**Деплой API.** Render деплоїть API тільки після успішних перевірок коміту (`autoDeployTrigger: checksPass` у `render.yaml`) і лише тоді, коли змінилися файли API, спільного пакета або залежностей.

**Кешування.**

- `node_modules` відновлюється з кешу, поки не змінилися `package-lock.json` і версія Node, тож `npm ci` виконується лише після зміни залежностей. Це робить спільний крок `.github/actions/setup`.
- Prettier пам'ятає вже перевірені файли за вмістом (`.cache/prettier`).

Перед першим деплоєм потрібно один раз увімкнути Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
