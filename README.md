# KrokLingo

Інтерактивний тренажер для підготовки до іспиту **«Крок 1. Стоматологія»** англійською мовою: симуляція іспиту з таймером, вільне тренування за темами та словник невідомих слів із миттєвим перекладом.

Працює повністю у браузері. Бекенду немає, усі дані зберігаються в `localStorage`.

**Демо:** https://toodyann.github.io/KrokLingo/

## Можливості

- **Головна:** дашборд активності й успішності за 7, 30 чи 90 днів або за весь час. Зверху ряд показників: серія днів, кількість відповідей, точність, нові слова, час навчання, зі зміною відносно попереднього періоду. Нижче графіки відповідей за днями, росту словника й результатів спроб відносно порогу, а також загальна точність і точність за темами. Графіки зроблені на [Recharts](https://recharts.github.io/).
- **Симуляція іспиту:** 50 завдань, зворотний таймер на 100 хвилин, автоматичне завершення, коли час вийде. Кількість завдань, час і поріг змінюються в налаштуваннях.
- **Вільне тренування:** без обмеження часу; можна вибрати збірники й теми, задати кількість питань або повторити лише ті, де були помилки.
- **Клікабельний текст:** кожне англійське слово в питаннях, текстах для читання та варіантах відповідей можна натиснути. На комп'ютері переклад з'являється в поповері біля слова, на телефоні — в аркуші знизу (закривається свайпом). Слова, які вже є у словнику, підсвічуються маркером у всіх текстах.
- **Словник невідомих слів:** кожне натиснуте слово автоматично зберігається. Слова можна редагувати (уточнити медичне значення, додати примітку), позначати вивченими, видаляти, повторювати картками та експортувати в `.txt` чи `.docx`.
- **Статистика наживо:** під час тесту видно таймер, номер питання, кількість правильних і неправильних відповідей та поточний відсоток.
- **Історія:** усі спроби, згруповані за днями, з фільтром за режимом; з кожної можна перейти до детального звіту.
- **Підсумковий звіт:** бали, витрачений час, відсоток, вердикт «склав / не склав» (поріг за замовчуванням 40%), детальний розбір кожного питання та список нових слів цієї сесії.
- **Імпорт збірників** у форматі JSON і **резервна копія** всіх даних.

## Банк питань

Близько 5500 питань двома мовами: 3193 англійською (117 оригінальних і понад 3000 з реальних буклетів 2006–2024) і 2268 українською (буклети 2010–2026). Мову питань для тестів, іспиту й тренування вибирають перемикачем на сторінці «Тести»; історія й результати показують обидві. Переклад слів по кліку працює для англійських питань. Банк зберігається на сервері (`apps/api/bank/*.json` → таблиці `bank_*`), застосунок отримує його через `GET /api/bank` і тримає копію в IndexedDB: повторні запуски миттєві й працюють офлайн, а зміни підтягуються у фоні.

| Збірник | Що всередині |
| --- | --- |
| Базові медичні дисципліни (88) | оригінальні ситуаційні задачі з поясненнями |
| Професійна англійська (29) | оригінальні: термінологія, граматика, читання (4 тексти) |
| Буклет 2006 … Буклет 2022 | офіційні англомовні буклети ЦТ «Крок 1. Стоматологія» (2006, 2019, 2021, 2022 і доповнення інших років — з посібника БДМУ) |
| Англійська 2022, 2023, 2024 (97–117) | іспит з англійської мови професійного спрямування: тексти для читання і клінічні питання |
| Буклет 2010 … 2026 (укр.) | україномовні буклети ЦТ: ЄМУ (2010–2024) і medical-club (2020–2026) |

Питання з буклетів, що повторюються в різні роки, лишаються лише в найновішому. Теми для них визначено автоматично за ключовими словами, тож де-не-де тема може бути неточною.

Теми відповідають дисциплінам Кроку 1, великі розбиті на частини (`src/data/topics.ts`): медична біологія; анатомія — загальна та голови, шиї й зубів; гістологія та цитологія; ембріологія (зокрема розвиток зуба); фізіологія; біохімія; мікробіологія та вірусологія; імунологія; патологічна фізіологія; патологічна анатомія; фармакологія; а також термінологія та читання. Джерела й скрипти збірки — у [`scripts/booklets`](apps/api/scripts/booklets/README.md).

Власні збірники можна додати через імпорт JSON (див. нижче).

### Вбудований словник

Для слів оригінальних питань є офлайн-переклад: близько 1400 базових форм. Лематизатор зводить словоформи до словникових (`teeth` → `tooth`, `caused` → `cause`, `bacteria` → `bacterium`). Слова з буклетів та імпортованих збірників, яких немає у вбудованому словнику, перекладаються онлайн через MyMemory; це можна вимкнути в налаштуваннях.

## Формат імпорту (JSON)

```json
{
  "collection": "Буклет 2024",
  "questions": [
    {
      "topic": "anatomy",
      "text": "Which nerve provides motor innervation to the muscles of mastication?",
      "options": ["Mandibular nerve", "Maxillary nerve", "Facial nerve", "Hypoglossal nerve", "Vagus nerve"],
      "correct": "A",
      "explanation": "Optional explanation."
    },
    {
      "topic": "reading",
      "passageTitle": "Dental caries",
      "passage": "Reading text shown above the question…",
      "text": "According to the text, …",
      "options": ["…", "…", "…", "…", "…"],
      "correct": 2
    }
  ]
}
```

- `correct` задається як літера (`"A"`–`"E"`), номер-рядок (`"1"`–`"5"`) або індекс від 0 (`0`–`4`).
- `topic` може бути одним із вбудованих (`anatomy`, `histology`, `physiology`, `biochemistry`, `microbiology`, `pharmacology`, `pathology`, `terminology`, `reading`) або будь-якою власною назвою.
- Питання з однаковим текстом `passage` згрупуються під одним текстом для читання.

Шаблон можна завантажити в розділі **Налаштування → Імпорт питань**.

## Дизайн

Компоненти побудовано на [shadcn/ui](https://ui.shadcn.com/) (Radix + Tailwind CSS v4). Візуальний орієнтир — стримані SaaS-інтерфейси на кшталт Linear і Vercel.

- **Одна тема.** Кольори, поверхні, радіуси й відступи задано токенами в `src/styles/tokens.css`. Змінні shadcn (`--primary`, `--card`, `--border`…) прив'язані до цих токенів у `src/index.css`, тож і компоненти shadcn, і власні елементи використовують ту саму палітру.
- **Тема.** Одна, чорна: фон `#000000`, сайдбар `#0A0A0A`, картки `#121212`, білі основні кнопки з чорним текстом, темно-сіра підкладка активного розділу й шість яскравих акцентів (лайм, фіолетовий, блакитний, кораловий, жовтий, рожевий) для карток статистики, дій і графіків. Заголовки й великі цифри набрано шрифтом Unbounded, текст — Geist. Маскот — усміхнений зуб — з’являється в привітанні, блоці прогресу й порожніх станах. Контраст тексту не нижчий за 4.5:1 (WCAG AA).
- **Сітка.** Контент займає ширину поруч із сайдбаром (до 1560 px) і розкладається по сторінках: сітка з 12 колонок на «Головній», основна колонка з закріпленою бічною панеллю на налаштуваннях тестів, результатах та історії, таблиця на всю ширину в словнику. Текст питання при цьому обмежено зручною шириною (~68 символів).
- **Адаптивність.** Від 768 px — сайдбар-рейка з іконками, яка розкривається поверх контенту при наведенні, а внизу — кнопка облікового запису (аватар, ім’я, пошта) з меню «Налаштування» / «Вийти»; телефон — таб-бар знизу й аркуші замість поповерів. Горизонтального скролу немає на жодній ширині.
- **Сигнатура.** Слова, які вже є у словнику, підсвічуються жовтим маркером у всіх текстах.
- **Рух і жести.** Аркуші тягнуться пальцем і закриваються з урахуванням швидкості жесту (пружинна анімація).
- **Доступність.** Цілі натискання 36–44 px (44 px на сенсорних екранах), видимий фокус, підказки до кнопок-іконок; враховано `prefers-reduced-motion`, `prefers-reduced-transparency` і `prefers-contrast`.
- **Скасування.** Оборотні дії можна відкотити кнопкою «Скасувати», без діалогів підтвердження.

## Застосунок (PWA)

KrokLingo встановлюється як застосунок: кнопка «Встановити» в **Налаштуваннях** (Chrome, Edge, Android), на iPhone — «Поділитися → На початковий екран».

- Service worker (`vite-plugin-pwa`, Workbox) кешує зібраний застосунок. Банк питань лежить в IndexedDB, тож після першого запуску все працює без інтернету. Запити до API й Supabase завжди йдуть у мережу.
- Нова версія сама не перезавантажує сторінку: з'являється «Доступна нова версія → Оновити», тож тест не перерветься. Оновлення перевіряються щогодини.
- Іконки: `public/pwa-*.png` і `maskable-icon-512x512.png` (зуб у безпечній зоні для круглих і заокруглених іконок), `apple-touch-icon.png`. Ярлики на іконці: «Тести» і «Словник».

## Стек

React 19, TypeScript, Vite, Fastify, Drizzle, PostgreSQL (Supabase), Tailwind CSS v4, shadcn/ui (Radix), Recharts, Oxlint, шрифт Geist (локально, з кирилицею). Кожна сторінка вантажиться окремим чанком. Пружинна анімація власна, `.docx` збирається власним ZIP-записувачем.

## Розробка

Монорепозиторій на npm workspaces. Потрібен Node.js 22.12+ (версія закріплена в `.nvmrc`).

```bash
nvm use
npm install
npm run dev
```

## Обліковий запис і бекенд

Без налаштування все працює як раніше: дані живуть у браузері. Коли задано змінні для синхронізації, у **Налаштуваннях** з'являється «Увійти через Google»:

- Після входу історія, словник, налаштування, незавершений тест і імпортовані збірники зберігаються в обліковому записі.
- Під час першого входу дані, зібрані в браузері до того, переносяться в обліковий запис.
- Далі кожна зміна відправляється на сервер. Без мережі зміни чекають і відправляються, щойно з'явиться зв'язок.
- Після виходу дані залишаються в обліковому записі, а з браузера прибираються.

Банк питань спільний для всіх і доступний без входу: `GET /api/bank` віддає його одним стиснутим документом з ETag. Під час старту API порівнює хеш файлів `apps/api/bank/*.json` з базою і, якщо вони змінилися, перезаписує таблиці `bank_collections`, `bank_passages` і `bank_questions`. Щоб додати питання, достатньо додати або змінити JSON-файл і задеплоїти API.

**Як це влаштовано:**

- **Вхід:** Supabase Auth через Google.
- **API:** Fastify перевіряє токен Supabase (через JWKS проєкту) і зберігає дані користувача в PostgreSQL Supabase через Drizzle.
- **Захист:** на всіх таблицях увімкнено Row Level Security без політик, тож доступ до даних можливий лише через API.

### Налаштування (один раз)

1. **Проєкт Supabase.** Створіть проєкт на [supabase.com](https://supabase.com). Знадобляться:
   - **Project URL** і **publishable (anon) key** — з *Project Settings → API*;
   - рядок підключення до бази — з *Connect → Connection string*.
2. **Вхід через Google.**
   - У [Google Cloud Console](https://console.cloud.google.com/apis/credentials) створіть OAuth Client ID (*Web application*). Як *Authorized redirect URI* вкажіть `https://<project-ref>.supabase.co/auth/v1/callback`.
   - У Supabase увімкніть *Authentication → Sign In / Providers → Google* і вставте Client ID та Secret.
   - У *Authentication → URL Configuration* додайте до *Redirect URLs* `https://toodyann.github.io/KrokLingo/` і `http://localhost:5173/`.
3. **База даних.** Створіть `apps/api/.env` за зразком `apps/api/.env.example` і застосуйте міграції:
   ```bash
   npm run db:migrate -w @kroklingo/api
   ```
4. **API.** Локальний запуск: `npm run dev:api` (порт 8787).

   **Продакшн на Render** (безкоштовний план) уже описано в [`render.yaml`](render.yaml):
   - *Render → New → Blueprint* → виберіть цей репозиторій.
   - Заповніть `DATABASE_URL` і `SUPABASE_URL`, решта змінних уже задана.
   - Міграції застосовуються під час старту (`MIGRATE_ON_START=true`). Нові пуші в `main`, що змінюють API, деплояться автоматично.
   - Адреса сервісу (`https://kroklingo-api.onrender.com` або схожа) — це і є `VITE_API_URL`.
   - Безкоштовний сервіс засинає без запитів, тож перший запит після паузи триває 30–60 с.

   **Інший хостинг з контейнерами** (Fly.io, Railway, Cloud Run): образ збирається з кореня репозиторію командою `docker build -f apps/api/Dockerfile -t kroklingo-api .`, змінні середовища ті самі.

   Перевірка після деплою:
   - `GET /health` відповідає `{"ok":true}`;
   - `GET /ready` додатково перевіряє з'єднання з базою;
   - `CORS_ORIGINS` має містити `https://toodyann.github.io`.
5. **Фронтенд.**
   - Для розробки: `apps/web/.env.local` за зразком `apps/web/.env.example`.
   - Для GitHub Pages: змінні репозиторію `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_API_URL` (*Settings → Secrets and variables → Actions → Variables*). Наступний деплой увімкне вхід на сайті.

## Деплой

Кожен пуш у `main` перевіряє код (lint, тести всіх пакетів), збирає фронтенд і публікує його на GitHub Pages (`.github/workflows/deploy.yml`). Щоб прямі посилання на розділи працювали на Pages, збірка копіює `index.html` у `404.html`.

Перед першим деплоєм потрібно один раз увімкнути Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
